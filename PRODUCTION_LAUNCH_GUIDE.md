# Mehandi by Sana — Complete Local-to-Production Launch & Operations Guide (Option A: Managed PaaS)

This guide covers the complete end-to-end path from your local workspace to live production on **mehandibysana.com** using **Option A (Managed PaaS — Zero Server Maintenance)**:

- **Frontend Storefront (`frontend/`)**: **Vercel** (`https://mehandibysana.com`)
- **Backend & Medusa Admin (`backend/`)**: **Railway** (`https://api.mehandibysana.com`, Admin UI at `https://api.mehandibysana.com/app`)
- **Database**: **Railway Managed PostgreSQL** + Persistent Volume (`/app/studio-data`)
- **Media Storage**: **Cloudflare R2** (`https://media.mehandibysana.com`, free 10 GB + zero egress fees)
- **Payments**: **Razorpay** (UPI, Cards, NetBanking) + Cash on Delivery (PIN-aware)
- **Emails & Campaigns**: **Resend** (recommended over HTTPS on Railway) or **Brevo / SMTP** + Exported Customer List (`studio-data/exports/customer-emails.csv`)

## 1. Pre-Flight Verification (Local Workspace)

Before pushing to GitHub and deploying:

1. Verify local builds & types pass cleanly:
   ```bash
   # Backend TypeScript & clean CI dependency check
   cd backend && npx tsc --noEmit && npm ci --dry-run

   # Frontend TypeScript & ESLint check
   cd ../frontend && npx tsc --noEmit && npm run lint

   # Migration tool TypeScript check
   cd ../migration && npx tsc --noEmit
   ```
2. Verify Git never tracks secrets or exported customer emails:
   Confirm `.gitignore` ignores `.env`, `*.env`, `studio-data/*.log`, `studio-data/exports/`, `studio-data/*.csv`, `studio-data/*.txt`, `studio-data/*.dump`, and `studio-data/bridal-bookings.json`. Never commit `RAZORPAY_KEY_SECRET`, `RESEND_API_KEY`, or `studio-data/exports/`.
3. Push your repository to a private GitHub repo (`git push origin main`).

## 2. Option A Deployment: Managed PaaS (Zero Server Maintenance)

Deploy services in this exact order so each service receives the URLs/keys generated by the previous step:

**Order:** `Cloudflare R2` -> `Railway (PostgreSQL + Backend + Volume)` -> `Vercel (Frontend)` -> `DNS Records`

### Step 2A — Cloudflare R2 Media Storage

Medusa uses `@medusajs/medusa/file-s3` automatically whenever `S3_BUCKET`, `S3_ACCESS_KEY_ID`, and `S3_SECRET_ACCESS_KEY` are set (`backend/medusa-config.ts`). Without R2/S3, uploaded product images on Railway are wiped on redeploy.

1. Log into Cloudflare Dashboard -> **R2 Object Storage** -> **Create bucket**: `mehandibysana-media`.
2. Open the bucket -> **Settings** -> **Public access -> Custom Domains** -> connect **`media.mehandibysana.com`**.
3. Go to **R2 -> Manage R2 API Tokens -> Create API Token** (`Object Read & Write` on `mehandibysana-media`).
4. Save these credentials for Step 2B:
   - `S3_FILE_URL=https://media.mehandibysana.com`
   - `S3_BUCKET=mehandibysana-media`
   - `S3_REGION=auto`
   - `S3_ENDPOINT=https://<YOUR_CLOUDFLARE_ACCOUNT_ID>.r2.cloudflarestorage.com`
   - `S3_ACCESS_KEY_ID=<token_access_key>`
   - `S3_SECRET_ACCESS_KEY=<token_secret_key>`

> **Note on existing images:** Existing legacy product & portfolio URLs under `https://mehandibysana.com/wp-content/uploads/...` are already whitelisted in `frontend/next.config.ts`. If you plan to decommission your old WordPress hosting after cutover, copy `wp-content/uploads/` into `mehandibysana-media` on R2 (or update image URLs inside Medusa Admin).

### Step 2B — Deploy MedusaJS Backend + PostgreSQL on Railway

1. Create a new project in [Railway](https://railway.com) -> **Deploy from GitHub repo** (`mehandibysana`).
2. Add a **PostgreSQL** database service inside the same Railway project.
3. Configure the **Medusa Backend** service settings:
   - **Root Directory**: `backend`
   - **Build Command**: `npm run build`
   - **Start Command**: `cd .medusa/server && npx medusa db:migrate && npx medusa start`
   - **Healthcheck Path**: `/health`

   > **Why `cd .medusa/server`?** In MedusaJS v2, `medusa build` compiles the backend API to `.medusa/server/src` and bundles the `/app` Admin dashboard to `.medusa/server/public/admin`. Starting from `.medusa/server` guarantees `/app` Admin assets load in production (`NODE_ENV=production`) while Node automatically resolves dependencies from `backend/node_modules`.
4. Attach a **Persistent Volume** to the Backend service (so `pincode-rules.json`, `bridal-bookings.json`, audit logs, and email exports persist across deployments):
   - **Mount Path**: `/app/studio-data`
   - Add env var: `STUDIO_DATA_DIR=/app/studio-data`
5. Generate two strong 64-char secrets locally:
   ```bash
   openssl rand -hex 32   # use for JWT_SECRET
   openssl rand -hex 32   # use for COOKIE_SECRET
   openssl rand -hex 24   # use for PINCODE_ADMIN_SECRET
   ```
6. Add all **Backend Environment Variables** in Railway (**Backend Service -> Variables**):

   ```bash
   NODE_ENV=production
   PORT=9000

   # Linked automatically from Railway Postgres service reference:
   DATABASE_URL=${{Postgres.DATABASE_URL}}

   # Security
   JWT_SECRET=<64_char_hex>
   COOKIE_SECRET=<64_char_hex>
   PINCODE_ADMIN_SECRET=<random_secret>
   STUDIO_DATA_DIR=/app/studio-data
   STORE_SITE_URL=https://mehandibysana.com

   # CORS
   STORE_CORS=https://mehandibysana.com,https://www.mehandibysana.com
   ADMIN_CORS=https://api.mehandibysana.com
   AUTH_CORS=https://mehandibysana.com,https://www.mehandibysana.com,https://api.mehandibysana.com

   # Razorpay (Step 4)
   RAZORPAY_KEY_ID=rzp_live_xxxxxxxxxxxxxx
   RAZORPAY_KEY_SECRET=xxxxxxxxxxxxxxxxxxxxxx
   RAZORPAY_WEBHOOK_SECRET=xxxxxxxxxxxxxxxxxxxxxx

   # Cloudflare R2 Media Storage (Step 2A)
   S3_FILE_URL=https://media.mehandibysana.com
   S3_ACCESS_KEY_ID=xxxxxxxxxxxxxxxxxxxxxx
   S3_SECRET_ACCESS_KEY=xxxxxxxxxxxxxxxxxxxxxx
   S3_REGION=auto
   S3_BUCKET=mehandibysana-media
   S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com

   # Email Notifications & Campaigns (Step 5)
   RESEND_API_KEY=re_xxxxxxxxxxxxxxxxxxxxxx
   STUDIO_FROM_EMAIL="Mehandi by Sana <orders@mehandibysana.com>"
   STUDIO_ADMIN_EMAIL=sana@mehandibysana.com
   ```

7. In Railway Backend **Settings -> Networking -> Custom Domain**, add **`api.mehandibysana.com`**.
8. Seed your production database (see [Section 3](#3-importing-the-latest-woocommerce-database-local--production)) and create your admin login:
   ```bash
   # Using Railway CLI linked to backend service:
   railway run npx medusa user -e sana@mehandibysana.com -p '<STRONG_ADMIN_PASSWORD>'
   ```
9. Sign in at **`https://api.mehandibysana.com/app`**, go to **Settings -> Publishable API Keys**, and copy the live `pk_...` key for Vercel.
   Also seed/copy your wildcard pincode rules (`19*` -> ₹60, etc.) under **Pincode Shipping** (`/app/pincode-shipping`) or copy `studio-data/pincode-rules.json` onto the Railway volume.

## 3. Importing the Latest WooCommerce Database (Local & Production)

You have **three idempotent ways** to keep your Medusa PostgreSQL database synced with the latest WordPress/WooCommerce catalog, customers, and orders with **zero data loss**.

### Option 3A — Clone Your Already-Verified Local Database -> Railway (Fastest Initial Prod Seed)

Your local Postgres database (`medusa_mehandibysana`) already has **19 products**, **2,069 customers**, **3,496 orders**, your India (INR) region, and admin users imported. To push this exact state to Railway in one command:

1. In Railway **Postgres service -> Variables / Connect**, copy **`DATABASE_PUBLIC_URL`** (format: `postgresql://postgres:<PASSWORD>@<HOST>.proxy.rlwy.net:<PORT>/railway`).
2. Back up local & restore into Railway Postgres:
   ```bash
   # 1. Dump your local Medusa PostgreSQL database
   pg_dump "postgres://nazrul@localhost:5432/medusa_mehandibysana" \
     --no-owner --no-privileges -Fc -f studio-data/local-medusa-backup.dump

   # 2. Restore cleanly into Railway PostgreSQL
   pg_restore --clean --if-exists --no-owner --no-privileges \
     -d "postgresql://postgres:<PASSWORD>@<HOST>.proxy.rlwy.net:<PORT>/railway" \
     studio-data/local-medusa-backup.dump
   ```
3. Run `npx medusa db:migrate` (or redeploy Railway backend) so schema migrations match cleanly.

> **Never lose local runtime files:** Recreate or verify your rules in `https://api.mehandibysana.com/app/pincode-shipping` after restoring the DB, since `pincode-rules.json` and `bridal-bookings.json` live in `/app/studio-data` (the Railway volume), not in Postgres.

---

### Option 3B — Import a Newer WordPress `.sql` Dump (Delta Sync Without Duplicates)

Whenever you export a fresh `.sql` backup from WordPress (`phpMyAdmin`, `UpdraftPlus`, `WP-CLI db export`):

#### 1. Test Locally First
```bash
# Single command from repo root:
npm run import:prod-sql -- /path/to/latest-wc-dump.sql
```
What this does automatically:
1. Parses the MySQL dump into `migration/data/raw/` and `migration/data/transformed/` (`categories.json`, `products.json`, `customers.json`, `orders.json`).
2. Runs `backend/src/scripts/sync-migrated-data.ts`: upserts categories & products and idempotently inserts any new customers (skipping existing emails).
3. Runs `backend/src/scripts/import-all-orders.ts`: imports only new orders whose `woo_order_id` is not already in Medusa (zero duplicate orders!).

#### 2. Push the Same Delta Directly to Production (Railway)
```bash
# Step 1: Parse latest SQL dump cleanly into migration/data/transformed/
npm run migrate:sql -- /path/to/latest-woocommerce-backup.sql

# Step 2: Sync new products, customers, and orders straight into Railway Postgres
cd backend
DATABASE_URL="postgresql://postgres:<PASSWORD>@<HOST>.proxy.rlwy.net:<PORT>/railway" \
  npx medusa exec ./src/scripts/sync-migrated-data.ts

DATABASE_URL="postgresql://postgres:<PASSWORD>@<HOST>.proxy.rlwy.net:<PORT>/railway" \
  npx medusa exec ./src/scripts/import-all-orders.ts
```

## 4. Razorpay Integration (Test Mode -> Live Mode + Webhooks)

Your storefront & backend already have full Razorpay Checkout + HMAC-SHA256 verification + webhook auditing implemented:

- **Frontend Checkout UI**: `frontend/src/components/cart/CheckoutHandoffClient.tsx` (loads `checkout.razorpay.com/v1/checkout.js`, themed `#d9541e`)
- **Next.js API Proxy**: `/api/razorpay/create-order` and `/api/razorpay/verify-payment` (adds Medusa publishable key server-side)
- **Medusa Store API**: `POST /store/razorpay/create-order` & `POST /store/razorpay/verify-payment` (constant-time `crypto.timingSafeEqual` verification before calling `createMedusaStoreOrder`)
- **Razorpay Webhook**: `POST /webhooks/razorpay` (with `preserveRawBody: true` enabled in `backend/src/api/middlewares.ts`, logging verified events to `studio-data/razorpay-webhooks.log`)

### Step 4A — Test Locally with Test Keys (`rzp_test_...`)
1. Log into [Razorpay Dashboard](https://dashboard.razorpay.com) -> switch top bar to **Test Mode**.
2. Go to **Account & Settings -> API Keys -> Generate Key**.
3. Put keys into `backend/.env`:
   ```bash
   RAZORPAY_KEY_ID=rzp_test_xxxxxxxxxxxxxx
   RAZORPAY_KEY_SECRET=xxxxxxxxxxxxxxxxxxxxxx
   RAZORPAY_WEBHOOK_SECRET=local_webhook_secret_123
   ```
4. Restart `npm run dev` in `backend/`, add a product to bag at `http://localhost:3000`, proceed to `/checkout`, select **Razorpay Online**, and test using Razorpay UPI (`success@razorpay`) or test card details.
5. Verify a `MBS-...` order appears in `http://localhost:9000/app/orders` and `http://localhost:3000/track-order`.

### Step 4B — Switch to Live Production Mode (`rzp_live_...`)
1. Complete Razorpay KYC & Website compliance verification (linked to `https://mehandibysana.com`, Privacy Policy, Terms & Conditions, and Contact pages — all live routes on your storefront).
2. Switch Razorpay Dashboard to **Live Mode** -> **Account & Settings -> API Keys -> Generate Live Key**.
3. Set `RAZORPAY_KEY_ID=rzp_live_...` and `RAZORPAY_KEY_SECRET=...` inside **Railway Backend -> Variables**.
4. Configure the **Live Webhook** in **Razorpay Dashboard -> Account & Settings -> Webhooks -> + Add New Webhook**:
   - **Webhook URL**: `https://api.mehandibysana.com/webhooks/razorpay`
   - **Secret**: Choose a strong random string (copy the exact same value to `RAZORPAY_WEBHOOK_SECRET` in Railway)
   - **Alert Email**: `sana@mehandibysana.com`
   - **Active Events**:
     - `payment.captured`
     - `order.paid`
     - `payment.failed`

## 5. Email Service Integration (Order Confirmations, Bookings & Owner Alerts)

`backend/src/lib/notifications.ts` powers transactional emails with branded HTML + plain-text layouts (`#ffffff` background, `#111111` ink, `#d9541e` CTA buttons with `#fceee3` text) whenever:
1. An order is confirmed (`order_confirmed` -> includes Track Order link).
2. A bridal/studio inquiry is submitted on `/contact` (`bridal_booking_received`).
3. You click **Confirm** on a booking in Medusa Admin `/app/bridal-bookings` (`bridal_booking_confirmed`).
4. Any new order or inquiry arrives -> sends a **Studio Owner Alert** to `STUDIO_ADMIN_EMAIL`.

It supports **three providers automatically** (priority order):

| Provider | Env Variables Required | Best For |
| --- | --- | --- |
| **1. Resend (Recommended)** | `RESEND_API_KEY` | Managed PaaS (Railway/Vercel). Sends over HTTPS port `443` — never blocked by cloud firewalls. Free tier: 3,000 emails/mo. |
| **2. Brevo (Sendinblue)** | `BREVO_API_KEY` | Built-in CRM + free 300 emails/day via HTTPS API. |
| **3. Custom SMTP (`nodemailer`)** | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Zoho Mail, Google Workspace App Password, Hostinger, or AWS SES. *(Note: some cloud PaaS hobby plans restrict outbound port 25/587; prefer Resend or Brevo HTTPS on Railway.)* |

### Step 5A — Recommended Setup with Resend
1. Create a free account at [resend.com](https://resend.com).
2. Go to **Domains -> Add Domain -> `mehandibysana.com`**.
3. Add the **DKIM** (`TXT`), **SPF** (`TXT`/`MX` on `send.mehandibysana.com`), and optional **DMARC** (`_dmarc.mehandibysana.com`) records shown by Resend to your DNS provider (Cloudflare / domain registrar).
4. Once **Verified**, go to **API Keys -> Create API Key** (`Sending access` or `Full access` if using Broadcasts/Audiences).
5. Add to **Railway Backend Variables** (and `backend/.env` locally if testing):
   ```bash
   RESEND_API_KEY=re_xxxxxxxxxxxxxxxxxxxxxxxxxx
   STUDIO_FROM_EMAIL="Mehandi by Sana <orders@mehandibysana.com>"
   STUDIO_ADMIN_EMAIL=sana@mehandibysana.com
   STORE_SITE_URL=https://mehandibysana.com
   ```
6. Test right away inside **Medusa Admin -> Email Campaigns -> Send Test** (`https://api.mehandibysana.com/app/email-campaigns`).

### Step 5B — Alternative Setup Using Zoho Mail / Google Workspace SMTP
If you prefer SMTP instead of Resend (`RESEND_API_KEY` and `BREVO_API_KEY` left empty):
```bash
# Example: Zoho Mail India SMTP
SMTP_HOST=smtp.zoho.in
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=orders@mehandibysana.com
SMTP_PASS=<ZOHO_APP_SPECIFIC_PASSWORD>
STUDIO_FROM_EMAIL="Mehandi by Sana <orders@mehandibysana.com>"
STUDIO_ADMIN_EMAIL=sana@mehandibysana.com
```
*(If on Railway free/hobby tier and port `465`/`587` times out, switch immediately to `RESEND_API_KEY` or `BREVO_API_KEY`.)*

### Domain Hygiene Note Before Sending (Important!)
From your live database domain audit:
- `1,959` `@gmail.com`, `21` `@yahoo.com`, `13` `@icloud.com`
- **14 typo domains detected**: `11` `@gmail.con` and `3` `@gamil.com`

Clean out unroutable `.con` / typo domains before uploading to a campaign tool so your bounce rate stays low and your domain doesn't land in Spam:
```bash
# Creates a bounce-safe CSV excluding obvious typo domains:
grep -viE '@(gmail\.con|gamil\.com|yahoo\.con|hotmail\.con),' \
  studio-data/exports/customer-emails.csv \
  > studio-data/exports/customer-emails-clean.csv
```
